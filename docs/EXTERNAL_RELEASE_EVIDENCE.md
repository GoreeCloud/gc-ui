# GoreeCloud UI — post-commit Stable evidence schema

This is a **procedure** for an eventual approved 1.0.0 release, not a claim that such approval exists. The current 1.0 draft candidate is unverified and MUST remain unpublished.

The release source commit must be finalized and checked in first. Commit SHA and actual archive hashes are established **after** committing and testing. Evidence therefore cannot be placed in the same tracked release-plan file without invalidating the hash. Place a separate JSON file at an absolute path outside the repository working tree, ideally in private, access-controlled release storage. Supply the path in the `GC_UI_RELEASE_EVIDENCE_FILE` environment variable only after reviewing each underlying URL, exact SHA, generated package hash, release controls and security/licensing decisions.

The schema requires `schemaVersion: 1`, `packageName: "@goreecloud/ui"`, `targetVersion: "1.0.0"`, the exact 40-character `sourceSha`, `decision: "verified"`, `maintainerApproval: true`, a nonempty `reviewer`, ISO `reviewedAt`, a GitHub issue/PR permalink `reviewUrl` documenting the approval, and **eight** `gates`. Each gate record must match one mandatory ID, have `status: "verified"` and at least one evidence item with `url`, identical `sourceSha`, `testedAt` and substantive `summary`. Required gate IDs are defined in `scripts/release-gate-core.mjs`; gate omissions, duplicates, remote HTTP, stale SHA and disabled mandatory gates fail closed. Never put private credentials or consumer data in links.

For clarity: the design is **metadata validation, not independent attestation**. URLs and names can be forged, and a reviewer must inspect them. The externally supplied file is not automatically considered canonical documentation or an official Stable release. The source still requires `plan.status="candidate-verified"`, `webFoundations.status="verified"`, `package.version="1.0.0"`, a clean Git checkout, approved branch controls, package/build/browser security/license checks, and exact evidence for each gate. This feature only fixes the hash self-reference; it does not authorize publication, forge approval, bypass branch protections, or close existing gates.

The default `npm run release:verify` and `prepublishOnly` remain blocked with no evidence file. Founder accessibility advisories and native/consumer deferrals are unchanged.
