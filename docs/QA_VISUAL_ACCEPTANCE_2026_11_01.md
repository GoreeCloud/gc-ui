## Corrective work in this review

1. A shared **experimental-only** `lab/floating-topbar.css` defines an inset rounded lens/surface, semantic token-based border/text, purposeful elevation and an opaque high-contrast/forced-color fallback. The existing Environment and Studio headers use this shared source; their controls, content and APIs are unchanged. Mobile appearance labels are kept on one line rather than wrapping into the previous two-line button.
2. `e2e/floating-lab-navigation.spec.mjs` measures real header geometry at 320, 375, 680, 840 and 1440px in LTR/RTL and forced-colors, checking accessible controls, 44px targets, button/brand nonoverlap, no horizontal scroll, and dark appearance switching.
3. Monochrome Octicons and Fluent icon previews contain fixed/default black paint and were nearly invisible in the full-resolution dark Environment screenshot. Their licensed sprite sources are unchanged; only the two demo cards identified by `data-gc-fixed-ink` receive a scoped dark-mode inversion filter. The after-fix full-resolution glyph crop was checked: all nine provider groups now have visible light monochrome samples. Regression checks preserve all original icon `href` references.
4. Local source, Chromium and Firefox functional checks and screenshot captures must pass at the exact proposed commit before merge. The PR needs **all exact-head GitHub quality/native gates** and post-merge readback; do not treat a local test as a deployed improvement.

## Accessibility and usability exceptions retained

- In the current 27-scenario experimental axe inventory, **27/27 reports** passed completeness verification with **zero confirmed axe violations**, but **30 inconclusive rule checks involving 316 node occurrences** remain. Of these, 25 color-contrast checks affect 311 nodes, and 5 ARIA-value checks affect 5 nodes. They are **not confirmed failures and not successful WCAG results**. Gradient/translucent/overlap context may require pixel-level composited inspection, and ARIA requires focus/accessibility-tree and relevant real assistive-technology review.
- The narrower four-scenario Seal installed-candidate test retains **four inconclusive node occurrences** even though its measured opaque menu text ratios pass. Firefox forced-color focused-menu contrast was repaired in earlier PR #147. That does not certify all OS color palettes or menu screen-reader speech.
- Existing Adaptive Shell regression `footer links retain a touch-safe gap above fixed mobile navigation at maximum scroll` passed during this review. The screenshot overlap is a **capture-location observation**, not independently verified blocked hit-target evidence.
- The new compact `Explore labs` native disclosure restores keyboard-operable access to all previously hidden desktop destinations: six Environment links and three Studio links. Open-state screenshots at 320px were inspected; source-pinned CI and owner visual/AT review remain required.
- Human optical/assistive-technology final approval has **not** been recorded; no screen-reader session, user-device native QA or exhaustive pixel-by-pixel comparison is claimed here.

## Decision and release boundary

**Result:** **Visual QA checkpoint = conditional, overall visual acceptance = pending.** The header inconsistency and verified dark glyph contrast defect are addressed on an experimental-only branch, not yet merged. After the corrected PR merges and its post-merge CI succeeds, close or explicitly retain the compact navigation issue, verify relevant light/dark/forced-color/motion/zoom and real assistive-technology scenarios, then request the authorized owner visual acceptance decision. Keep visual acceptance separate from full workspace stability and from the private Seal candidate lifecycle decision. Do not publish, deploy or change release labels merely because the images look polished.
