## November 6, 2026 — Forms autocomplete on-screen popup accessibility

**Reproduced on source main `03365f8869ccfe15738fbfe24acb9ade27e06487`:** At simulated desktop-browser mobile viewports **320×568**, **375×812**, **375×600** and **375×812 forced colors**, typing `d` into the Search projects combobox caused its visible-by-DOM listbox to appear entirely **below the actual viewport**. In both Chromium and Firefox at **375×812**, the input sat approximately at y=780–828 and the listbox at y=833–985 while the viewport bottom was y=812. This violates practical visible-on-focus usability even though `aria-expanded=true`, `aria-controls` and listbox role/option counts were correct. A 768×768 case already showed both within the viewport. The defect was detected through direct browser geometry (not inferred from axe rule classification).

**Scoped experimental Forms Lab correction:** After the listbox is populated and exposed with `aria-expanded=true`, call native `scrollIntoView({block:'nearest',inline:'nearest',behavior:'instant'})` on it. The browser scrolls only the necessary distance, keeps the **focused search input and suggestions** in the visual viewport, and avoids forcing an animated motion for users who prefer reduced motion. Local Forms Lab CSS supplies **12px block-end scroll margin** for breathing room; shared CSS, search matching, keyboard options, text values, ARIA semantics and exported component contracts remain unchanged.

**Regression:** The existing CI-run `e2e/forms.spec.mjs` suite gains six targeted states: 320×568 light, 375×812 light, 375×600 dark, 768×768 RTL, 1440×900 desktop, and 375×812 forced-colors. It requires both input and popup fully within the browser visual viewport with an 8px breathing boundary, no popup/input overlap or document horizontal overflow, preserved keyboard focus/active-descendant, and successful Escape dismissal. Each case attaches a JSON geometry record and a real screenshot **with the popup open**. Original regression red on Chromium: **4 failed / 2 passed**. Following the correction **6/6 Chromium + 6/6 Firefox** targeted local cases passed; full source/CI acceptance remains subject to separate verification. These browser viewport simulations do **not** establish iOS/Android virtual keyboard occlusion, TalkBack/VoiceOver speech, real mobile-device layout, or full WCAG/Seal acceptance.
